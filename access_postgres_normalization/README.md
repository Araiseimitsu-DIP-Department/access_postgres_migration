# PostgreSQL 正規化計画

Access由来の複数DBについて、開発環境で重複や参照関係を検証し、正規化後のテーブルとアプリの接続先を段階的に設計する。調査記録、作業手順、切替条件は [計画書](docs/plan.md) にまとめる。

## セットアップ

このリポジトリの Python 3.12 環境を使う。未セットアップの場合は、リポジトリ直下で既存の `requirements.txt` をインストールする。監査には既存依存の `psycopg2-binary` を使う。

| 環境変数 | 用途 |
|---|---|
| `NORMALIZATION_DEV_HOST` | 開発PostgreSQLのホスト。省略時は `192.168.1.120`。 |
| `NORMALIZATION_DEV_USER` | 両DBの対象テーブルを読み取れるロール。必須。 |
| `NORMALIZATION_DEV_PASSWORD` | 接続用パスワード。認証に必要な場合に設定する。 |

ポートは5432。接続設定は実行プロセスの環境変数から取得する。認証情報はリポジトリや実行記録に保存しない。

## 実行方法

リポジトリ直下で、開発環境を接続先に指定して実行する。

```powershell
python access_postgres_normalization/audit_delivery_labels.py
```

外観検査・現品票の両DBを読み取り専用で照合し、全11項目が一致する行数と双方にしかない行数を出力する。元データの値をログに出力せず、テーブルへの更新も行わない。失敗時は終了コード1を返す。照合は接続ごとに行うため、厳密な同時点比較が必要な場合は更新の止まった開発スナップショットを使用する。
